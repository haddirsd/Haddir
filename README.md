# حاضر | Haddir

منصة سودانية لاكتشاف الفعاليات وإدارة حجوزاتها وتذاكرها إلكترونياً. يحتوي هذا المستودع على تطبيق ويب مبني بـ Next.js وReact، مع تكامل Supabase للمصادقة والبيانات والعمليات الخلفية.

> **حالة المشروع:** يحتوي الكود الحالي على مسارات وواجهات متعددة موضحة أدناه. وجود الميزة في المستودع لا يعني وحده أن كل مساراتها اجتازت اختباراً شاملاً أو أنها جاهزة للإطلاق العام؛ راجع نتائج الاختبارات وحالة النشر قبل اعتماد أي إصدار.

## الوظائف الموجودة في الكود

- **الفعاليات:** استعراض الفعاليات وبطاقاتها وتفاصيلها، وأدوات الإدارة لإنشاء الفعاليات وتعديلها وإعدادات النشر والتذاكر.
- **الحجوزات والدفع:** اختيار التذاكر، إنشاء الحجز، عرض تعليمات الدفع، رفع إيصال التحويل، وإدارة مراجعة الحجوزات وطلبات الدفع.
- **التذاكر:** مساحة تذاكر العميل، عرض بيانات التذكرة ورمز QR، وتنزيل صورة التذكرة.
- **حساب العميل:** المصادقة، الملف الشخصي، التذاكر، الإشعارات وإعدادات إشعارات الويب.
- **الإدارة:** مساحات إدارة الفعاليات والحجوزات والمدفوعات والمستخدمين والنشاط والتقارير.
- **المعلن:** مساحة إحصاءات الفعالية ومؤشرات المبيعات.
- **بوابة الدخول:** مسح QR والإدخال اليدوي للتذكرة وسجل عمليات الفحص.
- **الخدمات الخلفية:** Supabase Edge Functions للبريد المرتبط بالحجز، وإشعارات الويب، وحذف حساب العميل.

هذه القائمة تصف مجالات موجودة في بنية الكود؛ ولا تعتبر بديلاً عن اختبار كل عملية على بيئة تشغيل فعلية.

## التقنيات

- Next.js 15 وReact 19
- TypeScript
- Supabase (حزمة @supabase/supabase-js)
- Tailwind CSS 4
- qrcode.react و@zxing/browser لعرض QR ومسحه

## بنية المستودع

| المسار | المسؤولية |
| --- | --- |
| app/ | صفحات Next.js ونقطة تشغيل التطبيق ومسار رفع إيصال الحجز |
| components/ | مكونات الواجهة المشتركة والتنقل والتخطيط |
| features/auth/ | المصادقة |
| features/events/ | الفعاليات وتفاصيلها وإدارتها |
| features/booking/ | الحجز والدفع والإيصالات وإدارة الطلبات |
| features/customer-account/ | الملف الشخصي والتذاكر والإشعارات |
| features/admin/ | مساحات الإدارة والتقارير والنشاط |
| features/advertiser/ | إحصاءات المعلنين |
| features/gatekeeper/ | التحقق من التذاكر عند الدخول |
| features/users/ | إدارة المستخدمين |
| lib/ | إعدادات ومساعدات مشتركة |
| supabase/functions/ | مصادر Edge Functions |
| supabase/migrations/ | ملفات SQL الخاصة بتغييرات قاعدة البيانات |

## تشغيل المشروع محلياً

يتطلب Node.js وبيئة Supabase وإعداد متغيرات البيئة التي يقرأها التطبيق. لا تضع مفاتيح الخدمة أو الأسرار في المستودع.

```bash
npm install
npm run dev
```

أوامر الفحص والبناء المتاحة:

```bash
npm run lint
npm run build
```

## قاعدة البيانات وSupabase

توجد ملفات SQL داخل supabase/migrations/، كما توجد مصادر Edge Functions داخل supabase/functions/. راجع [دليل Supabase](supabase/README.md) قبل تنفيذ أي تغيير على قاعدة البيانات أو نشر وظيفة خلفية.

**تنبيه مهم:** وجود ملفات migrations في المستودع لا يعني أن سجلها التاريخي قد طوبق بالكامل مع سجل قاعدة الإنتاج، ولا يعني أن تشغيلها دفعة واحدة على مشروع قائم آمن. يجب مراجعة دليل Supabase وتقارير مطابقة السجل قبل أي تطبيق.

## الاختبارات والنشر

- شغّل الفحوصات محلياً أو عبر GitHub Actions قبل اعتماد التغييرات.
- اختبر المصادقة والصلاحيات وRLS وواجهات PostgREST ومسارات الحجز والدفع والتذاكر على بيئة اختبار منفصلة.
- لا تنفذ migrations على الإنتاج ولا تنشر Edge Functions اعتماداً على وجود ملفات المصدر فقط؛ اتبع إجراءات المراجعة والتحقق الخاصة بكل بيئة.
- النشر الفعلي للتطبيق يتم عبر إعدادات Vercel المرتبطة بالمستودع.

## مبدأ التوثيق

يصف هذا الملف بنية الكود الموجودة حالياً، وليس خارطة تنفيذ قديمة أو ضماناً باكتمال جميع المتطلبات. حدّثه عند إضافة أو إزالة مجال رئيسي، وحافظ على توثيق الفجوات المعروفة بوضوح.
